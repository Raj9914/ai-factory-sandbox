# Experiments

One folder per 48-hour experiment. The experiment ID is `<slug>-<YYYYMMDD>` (the same ID used in `docs/PRD.md`, analytics UTM campaigns and cost logs).

```text
experiments/
  <id>/
    README.md        # brief: hypothesis, hour 0 (ISO), owner, links to PRD sections and issues
    COST_LOG.md      # from docs/templates/COST_LOG_TEMPLATE.md; actual figures only (cost-log.md also accepted)
    runs.jsonl       # one JSON object per agent run (format below)
    cost.md          # generated by scripts/experiment_cost.py; do not edit by hand
    HOUR_24.md       # from docs/templates/HOUR_24_DECISION_TEMPLATE.md (KEEP_SCOPE / CUT_SCOPE)
    HOUR_48.md       # from docs/templates/HOUR_48_DECISION_TEMPLATE.md (BUILD / PIVOT / KILL / INCONCLUSIVE)
    evidence/        # smoke output, exported metric counts, redacted screenshots
```

## Cost roll-up (`runs.jsonl` → `cost.md`)

Append one line to `runs.jsonl` per agent (Zeroshot) run, copied from `zeroshot status <run>` (`metadata.tokenUsage`, and the dollar cost only if the provider reported one):

```json
{"run_id": "zs-abc123", "issue": 42, "tokens": {"input": 1200, "output": 300, "cache_read": 5000, "cache_creation": 0}, "cost_usd": 0.42}
```

| Field | Required | Meaning |
|---|---|---|
| `run_id` | yes | Unique run ID (string). Duplicates are skipped and reported. |
| `issue` | yes | Issue number or reference the run worked on. |
| `tokens` | yes | Object with non-negative integers `input`, `output`, `cache_read`, `cache_creation` (a missing key counts as 0). |
| `cost_usd` | no | Actual dollar cost reported by the provider. Omit it or use `null` when unknown (e.g. subscription runs); never write an estimate or `0` for an unknown cost. |

Then run, offline (no network or `gh` calls):

```bash
python3 scripts/experiment_cost.py experiments/<id>   # --cap 25 is the default USD planning cap
```

It reads `runs.jsonl` and the `Actual USD` column of the manual cost log (`cost-log.md`, or `COST_LOG.md`; empty or `NOT AVAILABLE` means unknown) and writes `cost.md` with the dollar total, the number of runs and manual entries with unknown cost, token totals and the cap status. Unknown costs are counted separately, never as 0, and make the total a **lower bound**. Spend above the cap produces an explicit `OVER CAP` line. Malformed lines are skipped and listed under "Skipped input".

Rules:
- Record actual figures only; write `NOT MEASURED` or `NOT AVAILABLE` instead of estimating.
- No personal data: store counts and anonymised summaries, never raw user records.
- Decisions are drafted by agents and made by a human. Do not edit a decision file after the human records the verdict; add a dated note instead.
